## Main Content

IoT Copilot utilizes MongoDB Atlas as its primary database, with Mongoose acting as the Object Data Modeling (ODM) layer.

### 1. Mongoose Models (`server/src/models/`)

#### `Project` (`Project.ts`)
Stores the IoT projects generated by the AI or created manually by users.
- **Fields:**
  - `user`: ObjectId (Ref: User) - Owner of the project.
  - `title`: String (required)
  - `description`: String
  - `status`: Enum (`'pending'`, `'in-progress'`, `'completed'`, `'paused'`)
  - `category`: String
  - `progress`: Number (0-100)
  - `architecture`: Object (Hardware list, MCU, Cloud provider, Protocols)
  - `milestones`: Array of Objects (title, status, date)
- **Indexes:** 
  - `{ user: 1 }` for fast retrieval of a user's projects.
  - `{ status: 1 }` for filtering projects on the dashboard.

#### `Activity` (`Activity.ts`)
An event-sourcing ledger that tracks every significant action a user takes in the platform. Used to populate the Dashboard Activity charts.
- **Fields:**
  - `user`: ObjectId (Ref: User)
  - `type`: String (e.g., `'project_created'`, `'module_completed'`, `'login'`)
  - `title`: String
  - `description`: String
  - `metadata`: Mixed Object (Flexible field for storing context, like project ID or skill ID)
  - `createdAt`: Date
- **Indexes:**
  - `{ user: 1, createdAt: -1 }` heavily optimized for loading the chronological dashboard feed.

#### `AIMemory` (`AIMemory.ts`)
Stores contextual data about the user's past AI interactions to provide long-term memory for the AI Mentor.
- **Fields:**
  - `user`: ObjectId (Ref: User)
  - `context`: String (Summary of what the user is currently struggling with or working on)
  - `topics`: Array of Strings (Tags for fast filtering)
  - `lastInteraction`: Date

#### `LearningPath` (`LearningPath.ts`)
Tracks the user's progress through educational modules.
- **Fields:**
  - `user`: ObjectId (Ref: User)
  - `modulesCompleted`: Array of Strings
  - `currentSkillLevel`: Number
  - `radarData`: Array of Objects (skill names and values for the dashboard RadarChart)

#### `Comment` (`Comment.ts`)
For community features and shared project discussions.
- **Fields:**
  - `project`: ObjectId (Ref: Project)
  - `author`: ObjectId (Ref: User)
  - `content`: String
  - `createdAt`: Date

### 2. Better Auth Collections
Better Auth manages its own collections directly via the MongoDB driver, bypassing Mongoose schemas to avoid conflict.
- **`user`**: Stores core identity (email, name, emailVerified, image, createdAt, updatedAt).
- **`session`**: Stores active sessions (expiresAt, ipAddress, userAgent).
- **`account`**: Stores OAuth provider links (if GitHub/Google auth is added later).

### 3. Relationships & Data Integrity
- The system is heavily normalized. Most collections use `user: ObjectId` to relate back to the Better Auth `user` collection.
- Because Better Auth creates users via the raw MongoDB driver, Mongoose models treat the `user` field as a standard ObjectId rather than enforcing a strict Mongoose `ref` population constraint during creation.
- When querying, `Activity` and `Project` queries are aggressively filtered by `user: req.user.id` to prevent cross-tenant data leakage.

### 4. Connection Lifecycle (`server/src/config/db.ts`)
- Mongoose is configured to use native promises.
- Connects using `MONGODB_URI` from the `.env` file.
- Handles connection drops and reconnects gracefully using Mongoose's built-in event listeners (`connected`, `error`, `disconnected`).
