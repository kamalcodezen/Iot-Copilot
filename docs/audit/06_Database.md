# Database Documentation: IoT Copilot AI

This document outlines the MongoDB database structure, schemas, and indexing strategies used in the project via Mongoose.

## Overview
The application uses MongoDB as its primary data store. Data modeling is handled by Mongoose, providing strict schema enforcement, typing (via TypeScript interfaces), and lifecycle hooks. 

*Note: The `User` schema is likely managed directly by the `better-auth` integration, so it does not have a dedicated Mongoose schema file in the `models` directory.*

---

## Collections & Schemas

### 1. `Project` (`IProject`)
- **Purpose:** Stores the core IoT projects created by users (or generated by the AI Project Planner).
- **Schema Highlights:**
  - `userId`: String (String used instead of ObjectId to align with better-auth's user IDs).
  - `title`, `description`: Text fields.
  - `category`: Enum (`smart-home`, `robotics`, etc.).
  - `difficulty`: Enum (`beginner`, `intermediate`, `advanced`).
  - `status`: Enum tracking lifecycle (`planning`, `in-progress`, `completed`, `paused`).
  - `components`: Array of objects (name, quantity, link).
  - `circuitDescription`, `code`: Strings for hardware/software implementation.
  - `progress`: Number (0-100).
- **Indexes:**
  - `{ userId: 1, status: 1 }`: Optimizes dashboard queries filtering user projects by status.
  - `{ title: 'text', description: 'text' }`: Text index to enable search functionality across public/community projects.

### 2. `AIMemory` (`IAIMemory`)
- **Purpose:** Acts as the conversation history and context engine for the AI. Instead of storing massive JSON blobs per chat, it stores individual messages.
- **Schema Highlights:**
  - `type`: Enum categorizing the interaction (`mentor`, `debug`, `interview`, `roadmap`, `recommendation`).
  - `role`: `user` or `assistant`.
  - `content`: The actual message text.
  - `metadata`: Contains `topic`, `projectId` (ObjectId ref), and `codeSnippet` to provide rich context back to the AI.
- **Indexes:**
  - `{ userId: 1, createdAt: -1 }`: Extremely important for quickly fetching the most recent chat history for a specific user to build the Gemini prompt.

### 3. `LearningPath` (`ILearningPath`)
- **Purpose:** Stores personalized educational roadmaps generated for the user.
- **Schema Highlights:**
  - `level`: `beginner`, `intermediate`, `advanced`.
  - `modules`: An array of sub-documents representing curriculum steps. Each module has a `status` (`locked`, `available`, `in-progress`, `completed`), `resources` (videos, docs), and `estimatedHours`.
  - `progress`: Overall completion percentage (0-100).
- **Indexes:** 
  - Implicit index on `userId` (via Mongoose `index: true`).

### 4. `Activity` (`IActivity`)
- **Purpose:** An append-only event log used to generate the user's dashboard statistics, recent activity feeds, and gamification (badges).
- **Schema Highlights:**
  - `type`: Strict enum of events (e.g., `project_created`, `debug_session`, `badge_earned`).
  - `description`: Human-readable summary.
  - `metadata`: Optional references (e.g., `projectId`, `badgeName`, `sessionDuration`).
- **Indexes:**
  - `{ userId: 1, createdAt: -1 }`: Optimizes the dashboard feed query.

### 5. `Comment` (Assumed)
- **Purpose:** Community interaction on public projects. (Code size is small, usually contains `projectId`, `userId`, `content`, and `likes`).

---

## Validation & Relationships
- **Validation:** Mongoose handles required fields, enums, string trimming, and max/min values (e.g., progress is clamped between 0 and 100). 
- **Relationships:** Because `better-auth` handles the User ID as a string, models reference `userId` as a `String` rather than a MongoDB `ObjectId`. However, internal relationships (like an `Activity` referencing a `Project` or an `AIMemory` referencing a `Project`) correctly use `Schema.Types.ObjectId` with the `ref` property, allowing `.populate()` queries.
